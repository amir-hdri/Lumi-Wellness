# گزارش بررسی فول‌استک Lumi Wellness

بررسی از ۵ نوامبر ۲۰۲۶ آغاز شد و در ۶ نوامبر ادامه یافت. دامنهٔ بررسی، سورس جاری Next.js/FastAPI، قرارداد API، کنترل نقش‌ها، دیتابیس، migration، جریان‌های اصلی رابط و پیکربندی استقرار است. نتیجهٔ اجرای محلی، تأیید استقرار واقعی Vercel یا بک‌اند عمومی محسوب نمی‌شود.

## پنل مدیریت و مربیان

بررسی با عمل کاربر آغاز می‌شود: دکمه یا فرم، درخواست API، کنترل نقش و دادهٔ ذخیره‌شده، سپس نمایش پس از بارگذاری مجدد. رفع موفقیت‌های ظاهری و کنترل مجوزها اولویت داشت.

| بخش | امکانات و رفتار نهایی | شاهد اصلی |
| --- | --- | --- |
| مدیریت حساب | ثبت عضو/مربی با رمز اولیه، ویرایش هویت و شعبه، تغییر وضعیت و نقش، تعیین رمز و حذف؛ حساب مدیر/پذیرش در تنظیمات قابل مدیریت است | تست ساخت حساب و منوی مجوزها؛ مرورگر واقعی ورود، ویرایش، پاک‌کردن شعبه، ارتقای نقش و حذف را می‌آزماید |
| دسترسی پذیرش | ثبت و ادارهٔ ورزشکار؛ ساخت کارکنان و ویرایش هویت/وضعیت دیگر کارکنان برای مدیر است | درخواست ممنوع 403 می‌گیرد و دادهٔ هدف تغییر نمی‌کند؛ گردش مجاز پذیرش آزموده شده است |
| عضویت | تخصیص پلن، ویرایش دوره/قیمت/تخفیف، توقف و فعال‌سازی، درخواست تمدید و تأیید مدیر | تست مالکیت و سهمیه، درخواست تکراری، منع دورزدن تأیید؛ مرورگر با reload |
| مالی | ثبت pending، تطبیق وضعیت‌های موفق/در انتظار/ناموفق/لغوشده/مسترد، ویرایش روش/یادداشت، چاپ و رسید متنی | تست وضعیت لغوشده/مسترد، API واقعی و download مرورگر؛ تازه‌شدن نمودار درآمد بدون reload آزموده است |
| پلن و شعبه | ساخت، ویرایش، فعال/غیرفعال و حذف با رسیدگی به تعارض وابستگی‌ها؛ تنظیمات عمومی واقعاً ذخیره می‌شود | آزمون‌های CRUD بک‌اند و گردش پلن در مرورگر |
| اعلان مدیریت | اطلاع‌رسانی گروهی/فردی و مشاهدهٔ درخواست‌های تمدید دریافت‌شده | آزمون نقش/مالکیت/خواندن و گردش درخواست عضویت |
| مربی و برنامه | انتخاب ورزشکار واقعی، ساخت پیش‌نویس، همهٔ روزهای هفته، افزودن/ویرایش/حذف/مرتب‌سازی حرکات و تغییر وضعیت با ذخیره | تست سازنده و مالکیت و خطاهای ذخیره؛ هر تغییر از API موجود عبور می‌کند |
| حرکات و الگوها | کتابخانه با فیلتر سختی واقعی، ساخت/ویرایش/حذف حرکت؛ کپی برنامهٔ متعلق به مربی بدون سابقهٔ تکمیل | آزمون enumها، خطای وابستگی، نسخه‌برداری و جبران شکست جزئی |
| ورزشکاران/اهداف/پیام | نمایش دادهٔ API، اهداف و پیشرفت و یادداشت‌ها، گفت‌وگوی واقعی و وضعیت خواندن | جدول شاگردان از داشبورد مربی با برنامه/پیشرفت/حضور واقعی، لینک برنامه و ویرایش هدف به API وصل شده‌اند؛ آزمون‌های قرارداد، مجوزها و مرورگر برای پیام‌ها |
| پروفایل هر دو پنل | ذخیرهٔ مشخصات، تغییر رمز و خروج پس از ابطال نشست | تست موفقیت و شکست API، دادهٔ فرم و logout |

ایمیل نامعتبر، وضعیت ناشناخته، شعبهٔ ناموجود و null هویت قبل از ذخیره رد می‌شوند؛ این موارد قبلاً از مسیر عمومی می‌توانستند حساب غیرقابل‌ورود یا پاسخ 500 بسازند. نام دکمهٔ دریافت رسید با خروجی متنی یکسان شده است؛ چاپ مرورگر امکان ذخیرهٔ PDF را فراهم می‌کند.

ساخت هدف نیز با قاعدهٔ مجوز ویرایش/حذف یکسان شد: پذیرش حق ساخت هدف ندارد و مربی نمی‌تواند هدف را به نام مربی دیگر ایجاد کند. هر دو دورزدن با آزمون درخواست واقعی بازتولید و سپس اصلاح شدند.

## سیاست‌ها و حدود حفظ‌شده

- ثبت‌نام عمومی نقش ورزشکار دارد؛ نقش، وضعیت و عملیات مالی در بک‌اند کنترل می‌شوند.
- مربی نمی‌تواند سیاست ساخت حساب کارکنان را دور بزند؛ مجوزهای موجود بک‌اند حفظ می‌شوند.
- طرح گرافیکی، رنگ‌ها، تایپوگرافی و منطق داده‌محور نمودار کپسولی بازنویسی سلیقه‌ای نشدند. اجزای ذخیره‌ساز موجود برای رفع قطع اتصال استفاده شدند.
- فیلدهایی مثل تخصص/سابقهٔ مربی و قیمت عمومی جلسه که قرارداد ذخیره نداشتند، به‌صورت ذخیره‌شده معرفی نمی‌شوند؛ قیمت واقعی در پلن عضویت است.
- پرداخت ثبت‌شدهٔ ورزشکار همچنان pending است. تأیید پرداخت و تأیید تمدید، عملیات مدیریتی مستقل‌اند؛ درگاه بانکی واقعی در این بررسی اضافه نشده است.

## Graphify

ابزار hosted در جلسه قابل فراخوانی نبود؛ با درخواست صریح کاربر، نسخهٔ محلی نصب‌شده استفاده شد. Corpus اولیه ۳۲۰ فایل، حدود ۲۲۰ هزار واژه: ۲۷۶ فایل کد، ۲۶ سند، ۱۸ تصویر. استخراج معنایی همهٔ ۴۴ فایل غیرکد را تا انتها پوشش داد و هر fragment پیش از merge اعتبارسنجی شد. روابط اسناد تاریخی ادعاهای همان سند هستند و وضعیت فعلی کد را به‌تنهایی ثابت نمی‌کنند.

گراف، گزارش ساختاری، HTML تعاملی، benchmark و provenance در `graphify-out/` هستند. snapshot اولیه در پوشهٔ محلی `initial-snapshot/` حفظ شده است. استخراج AST و معنایی اسناد با snapshot نهایی سورس تطبیق داده می‌شود؛ provenance زمان/هش فایل‌های نمایه‌شده را ثبت می‌کند. فایل‌های baseline و cache همراه خروجی نهایی وارد گیت نمی‌شوند. شمارش واقعی توکن مصرفی از ابزار ایجنت برنگشت؛ صفرهای سازگاری در فایل هزینه، اندازه‌گیری مصرف نیستند. هشدارهای integrity و پوشش ناقص نمادها باید همراه گراف خوانده شوند.

هشدارهای گراف در `graphify-out/graph-health.json` ثبت شده‌اند: endpointهای حل‌نشده، self-loop و روابط هم‌endpoint که در گراف بدون جهت ادغام می‌شوند. این نقشه تضمین کامل‌بودن روابط نیست؛ وابستگی‌های عمومی React/UI نیز hub هستند و centrality آن‌ها به‌تنهایی نقص معماری محسوب نمی‌شود. `backend/pyproject.toml` و `skills-lock.json` نماد AST مدل‌شده ندارند؛ فایل‌های پیکربندی را باید مستقیم خواند. فایل‌های دارای تنها file-level node و فاقد نماد جزئی هم در provenance نام برده می‌شوند. fingerprint فایل‌های منبع در provenance مبنای تطبیق سورس جاری است.
